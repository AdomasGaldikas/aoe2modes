# CBA Hero: Ascendants v1.0.9 candidate

This candidate makes Ascendants a code-defined scenario and repairs one real
gameplay asymmetry found by reviewing the v1.0.8 source. No gameplay system was
redesigned; the trigger, object, condition and effect totals are unchanged.

## Ascendants is now code-defined

- Removes `scenario.reference` and deletes `base.aoe2scenario`. That file was
  described as "the decompiled legacy reference" but was actually an output of an
  earlier Ascendants build: it declared `pending_builders_p1`, `p1k` and the other
  variables that `build.py` itself creates.
- `verify.compare` put the committed source and that reference **8,811 fields apart**
  over 57,741 checked (2,206 triggers / 40 variables in the file, 1,989 / 0 in the
  source). The two had not corresponded for some time, and nothing detected it: the
  test that appeared to prove the round trip decompiled the reference into a temporary
  directory and compared *that* against itself, never touching the committed package.
- Renames `generated/` to `scenario/` and rewrites all 13 file headers. They claimed
  "Generated by `aoe2modes decompile` — regenerating overwrites this file", but the
  package could not have been decompiler output: the emitter writes the `VARIABLES`
  table and its loop unconditionally, and neither was present. It had been hand-edited,
  so regenerating would have silently discarded that work.
- `aoe2modes verify` and `aoe2modes decompile` no longer apply to this mode.
  `aoe2modes audit` on the built file is the structural gate.
- The decompiler keeps a real round-trip test, now pointed at `chieftains_4v4` — a mode
  that genuinely still is a decompile — plus a synthetic scenario that pins
  trigger-variable ids and names across a decompile cycle.

## Gameplay fix: anti-trebuchet zones were not mirrored

- The eight `No trebs in pN base` kill zones were eight hand-written rectangles, and
  only one of them matched any mirror of another. `wall_cleanup_bounds`, ten lines
  away in the same function, was 8/8 mirror-consistent — so the convention was known
  and simply not applied here.
- **P4, P6, P7 and P8's zones stopped at 123 while their Castle rows sit at 125**, so
  none of those four players' Castles were inside their own anti-treb zone, while
  P1/P2/P3/P5 had all four covered. A Trebuchet parked beside a Castle was removed for
  half the lobby and survived for the other half, in a mode whose stated design is
  eight equal mirrored territories.
- Both tables are now derived from one canonical P3 rectangle through the V2 cell
  transform. All eight zones cover 4/4 of their own Castles, and each stays clear of
  its own rear route by construction (source rect starts at x=18; rear route land is
  x=14..16).

## Robustness

- Civilization array sizes are derived from `CIV_SPAWN_RULES` instead of a hardcoded
  `60` repeated in five places. Adding a civilization would previously have written
  past the end of a size-60 array at runtime, which `xs-check` cannot see.
- An unsupported civilization id now says so in chat instead of failing silently.
  Previously a player on a civilization released after this build got no army and no
  builder pairs with no explanation, which reads in-game as a broken scenario.
- Adds a build-time assertion that the trigger-variable id space is contiguous from 0
  and collision-free. Ids come from several independent allocators, and a collision
  rewires trigger logic without changing any visible field.
- Names the last two bare variable bases (`PENDING_BUILDER_VARIABLE_BASE`,
  `COMBAT_ROW_VARIABLE_BASE`) and interpolates them into the XS, so the Python and XS
  sides of every variable block are now stated once.
- Deletes `free_costs.py`. Its 128 lines of object ids were never imported by
  anything; costs are zeroed by the XS `main()` loop.

## Test and tooling quality

- Replaces the anti-trebuchet regression test. It restated the same literal table that
  `build.py` used, so it could not fail for a wrong-but-consistent value — and did not:
  it pinned the asymmetry above in place. It now asserts the properties (one mirror
  orbit; every zone covers its own four Castles) using an independent transform.
- `make check-ascendants` and the CI audit derive the scenario filename from
  `mode.toml` via a new `aoe2modes info --output-name`, instead of hardcoding a version
  that goes stale on every bump.
- CI now runs `aoe2modes audit`. Ascendants gates on it; the other modes are audited
  informationally, because `chieftains_ffa` inherits 24 dangling object references from
  the community scenario it was decompiled from.
- `aoe2modes audit`'s verdict line is ASCII, so a default-codepage Windows console no
  longer mangles it.

## Unchanged

Produces 3,383 uniquely named non-empty triggers, 1,076 objects, 11,384 conditions,
9,975 effects, and 97 variables — identical to v1.0.8. Passes the parser structural
audit with 0 errors and 0 warnings. 97 tests pass; `ruff` is clean.

File size: 113,335 bytes

SHA-256:
`9a9372baffa382797af14d31ad4324e26db2044f4d8369ebb0325b115c206342`

Definitive Edition multiplayer, pathfinding, and UI acceptance still require an
in-game check. The anti-trebuchet change is the one behavior difference from v1.0.8:
confirm that an enemy Trebuchet parked beside P4/P6/P7/P8's Castles is now removed the
way it always was for P1/P2/P3/P5.

The widened zones carry no collateral risk — each effect is filtered to
`TREBUCHET_PACKED` (331) owned by one specific enemy player, so it cannot touch a
friendly unit on a rear route regardless of area.
